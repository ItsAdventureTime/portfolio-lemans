# Writing standard

- Use US English for active app copy, documentation, guides, and new commit messages.
- Tone: professional, conversational, direct, and respectful.
- Lead with the outcome or action; prefer active voice, short sentences, and concrete next steps.
- Use common words; define unfamiliar acronyms on first use when needed.
- Remove hype, filler, repeated summaries, generic assurances, artificial formality, and unexplained jargon.
- Preserve technical identifiers, commands, API names, status values, and legal text.
- Before publishing, proofread for accuracy, coherent flow, US spelling, and readability aloud.
- Repository source of truth: `docs/WRITING-STYLE.md`.
